# 模型加密系统实现总结

## 🎯 功能概述

实现了基于**主板编号硬件绑定**和**参数异或混淆**的模型加密保护系统。

## 📋 核心文件

| 文件 | 功能 |
|------|------|
| `encrypt_models.py` | 模型加密脚本（支持多平台） |
| `model_decryptor.py` | 解密加载模块（内存加载，不落盘） |
| `test_encryption.py` | 功能测试验证脚本 |

## 🔐 加密流程

```
原始模型 (.pt/.pth)
    ↓
加载模型到内存
    ↓
对所有参数进行异或混淆 (XOR 0x55)
    ↓
Pickle 序列化
    ↓
AES-256-CBC 加密 (使用主板编号生成密钥)
    ↓
保存为 .enc 文件
```

## 🔓 解密加载流程

```
加密模型文件 (.enc)
    ↓
获取主板编号，生成 AES 密钥
    ↓
AES 解密
    ↓
Pickle 反序列化
    ↓
对所有参数进行异或还原 (XOR 0x55)
    ↓
直接加载到内存（不生成文件）
    ↓
torch.load() 加载为模型对象
```

## 🛡️ 安全特性

1. **硬件绑定**: 使用主板编号作为密钥种子，只能在特定机器上运行
2. **参数混淆**: 对模型参数进行异或处理，即使解密后参数也不是原始值
3. **AES-256-CBC**: 工业级加密标准
4. **内存加载**: 解密后的模型不写入磁盘，仅存在于内存中
5. **兼容性**: 同时支持加密文件和未加密文件

## 🔑 多平台支持

### Linux
- `/sys/class/dmi/id/board_serial` (主板序列号)
- `/sys/class/dmi/id/product_uuid` (产品UUID)
- `/etc/machine-id` (机器ID)

### Windows
- `wmic baseboard get serialnumber` (主板序列号)
- 注册表 `MachineGuid` (机器GUID)

### macOS
- `ioreg` 硬件 UUID
- MAC 地址（备用方案）

## 🚀 使用方法

### 加密所有模型
```bash
python encrypt_models.py
```

### 测试加密解密功能
```bash
python encrypt_models.py test
```

### 运行完整测试
```bash
python test_encryption.py
```

### 启动服务（自动加载加密模型）
```bash
python server.py
```

## 📝 文件格式

### 加密文件结构
```
[12 bytes] 魔数: 'MODEL_ENC_V1'
[1 byte]  XOR 密钥 (0x55)
[4 bytes] 异或参数数量
[16 bytes] AES IV
[N bytes]  AES 加密数据
```

## ⚠️ 注意事项

1. **机器绑定**: 加密的模型只能在相同主板上运行
2. **原文件保留**: 建议保留原始模型文件作为备份
3. **优先级**: 当 `.enc` 文件存在时，系统优先加载加密文件
4. **兼容性**: 如果加密文件不存在，系统会自动回退到原始文件

## 组合式检测接口

新增 `POST /detect/plate`，一次请求完成 AB 检测、图像预处理和镍板分类。
请求可以使用 `application/octet-stream` 直接发送图片字节，并通过 query 参数传入
`surface`、`plate_type`、`out_dir`；也可以使用 `application/json` 传入本地图片路径。
`plate_type` 为 `dianji` 时调用电积镍分类，为 `dianjie` 时调用电解镍分类。
